Установка и настройка basic_template_mobile_desctop

Пошаговое руководство для разработки web-версии, запуска Electron и сборки Android-приложения с подключением к Django API.

Web assetswww/ → dist/ через Vite
DesktopElectron entry: electron/main.js
AndroidCapacitor читает assets из dist/

1. Структура проекта

  • www/ — исходные HTML, CSS и JavaScript.
  • templates/ — Nunjucks-шаблоны интерфейса.
  • build/precompile.js — генерация www/templates.js.
  • vite.config.js — сборка из www/ в dist/.
  • electron/ — главное окно, preload-мост и IPC.
  • android/ — Android-проект Capacitor.
Важно: Electron загружает dist/index.html. Android также копирует web assets из dist/. Поэтому после изменения исходников сначала собирайте проект.

2. Требования

  • Node.js 22 LTS и npm.
  • Для Android: JDK 17, Android Studio, Android SDK 36 и Platform Tools.
  • Для запуска на Linux: графическая сессия и системные библиотеки Electron.
  • Для сетевого API: backend на компьютере с LAN-доступом, портом 8080 и health endpoint /api/ping/.

3. Установка зависимостей

Склонируйте репозиторий и откройте терминал в корне проекта — рядом с package.json:

git clone https://github.com/ExtaSsS4106/electron_desctop_mobile_template.git
cd electron_desctop_mobile_template
npm install

Если менялись зависимости или версии Node, повторите установку после проверки совместимости проекта.

4. Запуск и сборка desktop

Обычный запуск собирает web-часть и открывает Electron:

npm start

Сборка отдельно, затем запуск Electron:

npm run build
electron .

Сборка выполняет node build/precompile.js, затем Vite компилирует модули и CSS в dist/. При необходимости на Linux:

npm run build
electron --ozone-platform=x11 .

Для web-разработки запустите Vite:

npm run dev

Откройте URL, который напечатает Vite, обычно http://127.0.0.1:4173. Эта команда запускает web-сервер, не Electron.

Entry point: package.json указывает на electron/main.js. Не запускайте корневой main.js вместо electron ..
Важно: если на Linux Electron падает с такой ошибкой: 
[69972:1002/104513.329124:FATAL:sandbox/linux/suid/client/setuid_sandbox_host.cc:166]
        The SUID sandbox helper binary was found, but is not configured correctly.
        Rather than run without sandboxing I'm aborting now. You need to make sure that
        /home/user/.npm-global/lib/node_modules/electron/dist/chrome-sandbox
        is owned by root and has mode 4755.
        /home/user/.npm-global/lib/node_modules/electron/dist/electron exited with signal SIGTRAP
выставьте файлу chrome-sandbox владельца root и права 4755: 
sudo chown root:root /home/user/.npm-global/lib/node_modules/electron/dist/chrome-sandbox
sudo chmod 4755 /home/user/.npm-global/lib/node_modules/electron/dist/chrome-sandbox

5. Настройка API и локальной сети

Адрес backend

Резервный адрес API задаётся в www/index.html:

window.TASKFLOW_API_URL = 'http://192.168.1.180:8080/api';

Замените IP на адрес компьютера с Django в локальной сети. На физическом телефоне localhost и 127.0.0.1 означают телефон, не компьютер.

В Electron сначала выполняется динамический поиск: electron/main.js получает адреса интерфейсов, сканирует кандидатов и проверяет /api/ping/. Android использует заданный резервный URL: Electron preload там недоступен.

Запуск Django

Слушайте внешний интерфейс, чтобы телефон мог подключиться:

python manage.py runserver 0.0.0.0:8080

Компьютер и телефон должны быть в одной сети; firewall должен пропускать входящие подключения к порту 8080. Проверка с телефона:

http://<LAN-IP>:8080/api/ping/
Ожидаемый результат — HTTP 200 и, например, {"message":"pong"}. Убедитесь, что ping доступен без авторизации.

CORS для Android WebView

CORS настраивается в Django backend. Установите пакет:

pip install django-cors-headers

В settings.py добавьте приложение и middleware до CommonMiddleware:

INSTALLED_APPS = [
    'corsheaders',
    # остальные приложения
]

MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'whitenoise.middleware.WhiteNoiseMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'corsheaders.middleware.CorsMiddleware',
    'django.middleware.common.CommonMiddleware',
    # остальные middleware
]

CORS_ALLOWED_ORIGINS = [
    'http://localhost',
]

В проекте указано androidScheme: "http", поэтому Android origin обычно http://localhost. Если WebView сообщает другой Origin, разрешите именно его. После изменения настроек перезапустите backend. Preflight на login должен возвращать Access-Control-Allow-Origin.

Не используйте CORS_ALLOW_ALL_ORIGINS = True в production. Ограничьте также ALLOWED_HOSTS.

HTTP / HTTPS

Для локальной разработки включены androidScheme: "http" и cleartext: true. Это не production-конфигурация: для реального размещения используйте HTTPS.

6. Сборка Android APK

Из корня проекта выполните:

npm install
npm run build
npx cap sync android
cd android
./gradlew assembleDebug

Debug APK появится здесь:

android/app/build/outputs/apk/debug/app-debug.apk

Установить на подключённый телефон (из корня проекта):

adb install -r android/app/build/outputs/apk/debug/app-debug.apk

Или открыть Android Studio:

npx cap open android
После каждого изменения www/ выполните npm run build, затем npx cap sync android, пересоберите APK и установите его заново. Capacitor копирует ресурсы из dist/.

В текущем проекте Capacitor настроены webDir: "dist", androidScheme: "http" и cleartext: true.

Release

Для публикации создайте keystore и соберите подписанный APK/AAB через Android Studio. Не коммитьте keystore или пароли в репозиторий.

7. Хранение токенов

  • Electron: preload API и зашифрованный файл auth.json в пользовательском каталоге Electron через safeStorage.
  • Android/iOS: @aparajita/capacitor-secure-storage.
  • Обычный браузер: sessionStorage как отладочный fallback.

Общий адаптер этих вариантов находится в www/auth-storage.js.

8. Диагностика

Electron показывает пустое окно

  1. Запустите npm start, чтобы заново создать dist/.
  2. Проверьте, что существует dist/index.html.
  3. Откройте DevTools и проверьте Console.
  4. Убедитесь, что запуск идёт через electron ., который использует entry point из package.json.

Android не соединяется с API

  1. Проверьте LAN IP в www/index.html, а затем в dist/index.html.
  2. Проверьте, что телефон и backend доступны в одной сети и Django слушает 0.0.0.0:8080.
  3. Откройте ping endpoint непосредственно на телефоне.
  4. Проверьте Android WebView CORS origin и заголовки ответа.
  5. Выполните build, cap sync, Gradle build и установите свежий APK.

Изменения не появились на телефоне

Изменение www/ не меняет уже установленный APK. Повторите весь Android build flow. Устанавливайте именно файл android/app/build/outputs/apk/debug/app-debug.apk.
